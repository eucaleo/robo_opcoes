# 10.1_normalizacao_comprado_vendido

## Objetivo

Eliminar dupla interpretação futura entre os vocabulários de lado da posição:

- COMPRADO / VENDIDO
- LONG / SHORT
- C / V
- aliases legados como COMPRA, VENDA, BUY, SELL, quando aplicável

## Política oficial

| Camada | Vocabulário oficial |
|---|---|
| UI | COMPRADO / VENDIDO |
| API de estruturas | COMPRADO / VENDIDO |
| Repositório de estruturas | COMPRADO / VENDIDO |
| Canonical input de estrutura | COMPRADO / VENDIDO |
| Enriquecimento RTD de estrutura | COMPRADO / VENDIDO |
| Payload técnico de pricing | LONG / SHORT |
| Cálculo/payoff/métricas técnicas | LONG / SHORT, sempre via conversor central |

## Fonte única

A fonte única para normalização semântica de lado da posição é:

    domain/position_side.py

Funções oficiais:

    normalize_position_side(value) -> COMPRADO/VENDIDO
    to_pricing_engine_side(value) -> LONG/SHORT

## Regra principal

- Dentro de domínio/canonical/estrutura/UI, usar COMPRADO / VENDIDO.
- Na borda técnica de pricing/cálculo, converter para LONG / SHORT.
- Evitar normalizadores paralelos.
- Evitar conversões manuais espalhadas.
- Aliases legados podem ser aceitos na entrada, mas devem ser normalizados imediatamente.
